# Tableau / Power BI Build Guide

## Why this guide exists instead of a `.pbix` or `.twbx` file

A native Power BI (`.pbix`) file is a proprietary binary format for which no
supported Python or open-source library provides a reliable writer; it can be
produced only through Power BI Desktop. A Tableau (`.twbx`) file is
technically a zip archive containing an XML workbook and a data extract, but
constructing one without Tableau available for validation would not provide a
verifiable deliverable. The project therefore provides the following
reproducible alternatives:

1. **`data/processed/bi_export/*.csv`**: five clean, denormalised,
   BI-import-ready tables in a star-schema layout (the focus of this guide).
2. **`reports/nhs_procurement_dashboard.html`**: an interactive Plotly
   dashboard covering the same KPIs, viewable in any browser without BI
   software, generated by `src/analysis/dashboard.py`.
3. **This guide**: a field-level specification of the chart types and
   mappings required to reconstruct the star-schema dashboard in Tableau
   Desktop or Power BI Desktop.

## The star schema

| File | Grain | Rows | Role |
|---|---|---|---|
| `fact_transactions.csv` | one row per `trust_spend` transaction (contract-notice records included but with ML columns blank; see `is_ml_scored`) | 288,071 | **Fact table** |
| `dim_supplier.csv` | one row per scored supplier | 3,456 | Supplier dimension |
| `dim_category.csv` | one row per spend category | 238 | Category dimension |
| `dim_period.csv` | one row per pre/COVID/post period | 3 | Period dimension |
| `dim_month.csv` | one row per calendar month | 72 | Time dimension |

**Relationships to specify in Tableau/Power BI** (all left/many-to-one from
the fact table):
- `fact_transactions.supplier` → `dim_supplier.supplier`
- `fact_transactions.category` → `dim_category.category`
- `fact_transactions.period` → `dim_period.period_label`
- `fact_transactions.year_month` → `dim_month.year_month`

## Field reference

### `fact_transactions.csv`
| Field | Type | Notes |
|---|---|---|
| `record_id` | text | primary key |
| `source` | text | `NHS_England`, `Bradford_Teaching_Hospitals`, `United_Lincolnshire_Hospitals`, `UK_Contracts_Finder` |
| `entity` / `supplier` | text | buyer / seller name |
| `date`, `year`, `month`, `year_month` | date/int/text | transaction date breakdowns |
| `amount` | number | transaction value (£); for `record_type = contract_notice` this is a contract *ceiling* value, not incurred spend; filter to `record_type = trust_spend` for any spend total |
| `category`, `sub_category` | text | procurement spend category |
| `record_type` | text | `trust_spend` or `contract_notice` |
| `period` | text | `Pre-COVID` / `COVID` / `Post-COVID` |
| `is_new_supplier_flag` | bool | first-time-supplier flag (6-month burn-in applied) |
| `flag_direct_award_covid`, `flag_price_spike`, `flag_new_supplier_large_covid`, `flag_round_amount` | bool | individual audit red-flag rules |
| `rule_flag_count` | int | how many rules a record tripped (0-4) |
| `is_rule_flagged` | bool | any rule tripped |
| `is_ml_anomaly` | bool | Isolation Forest flag (98th-percentile cutoff); blank for `contract_notice` rows |
| `ml_anomaly_score` | number | raw Isolation Forest anomaly score; blank for `contract_notice` rows |
| `is_ml_scored` | bool | **filter on this** to restrict any ML-based visual to the 257,095 scored `trust_spend` records |
| `supplier_is_network_hub` | bool | multi-trust hub supplier (Phase 6D network analysis) |
| `composite_risk_score` | number 0-100 | Phase 7A composite risk score |
| `risk_tier` | text | `Low` / `Medium` / `High` / `Critical` / `Not scored` |
| `rule_flag_severity` | text | `rule_flag_count` binned to `None` / `Single` / `Double` / `Triple+` -- feeds decomposition-tree and Key Influencers visuals |
| `anomaly_score_zscore` | number | `ml_anomaly_score` standardised (z-score) within its own `period` -- lets a BI tool compare anomaly severity across periods on a common scale; blank wherever `ml_anomaly_score` is blank |
| `spend_pctile_in_category` | number 0-100 | `amount`'s percentile rank within its `category` -- flags unusually large/small spend relative to peers in the same category |

### `dim_supplier.csv`
`supplier`, `total_transactions`, `total_spend`, `mean_transaction_amount`,
`ml_anomaly_rate`, `mean_ml_anomaly_score`, `rule_flag_rate`,
`is_network_hub`, `composite_risk_score`, `risk_tier`, `community_id`,
`community_size` (co-occurrence network community from Phase 6D).

### `dim_category.csv`
`category`, `total_spend`, `n_transactions`, `n_periods_active`,
`mean_anomaly_rate_pct`, `mean_new_supplier_rate_pct`, `mean_hhi`,
`share_of_total_spend_pct`, `pct_change_pre_to_covid`,
`pct_change_covid_to_post` (the last two are `NaN` for categories with
fewer than 20 transactions, reflecting the Phase 7B noise-reduction cutoff).

### `dim_period.csv`
`period`, `period_label`, `months`, `avg_monthly_spend`,
`baseline_avg_monthly_spend`, `pct_deviation_from_baseline`, `avg_residual`,
`max_abs_residual` (all from the Phase 3 STL decomposition),
`ml_anomaly_rate_pct`.

### `dim_month.csv`
`year_month`, `total_spend`, `n_transactions`, `new_supplier_rate_pct`,
`period`, `hhi` (Herfindahl-Hirschman supplier-concentration index),
`ml_anomaly_rate_pct`.

## Suggested dashboard layout (mirrors `nhs_procurement_dashboard.html`)

| Panel | Data source | Chart type | Fields |
|---|---|---|---|
| KPI card: Total trust spend | `fact_transactions` filtered to `record_type = trust_spend` | Big Number / Card | `SUM(amount)` |
| KPI card: Transactions analysed | `fact_transactions` filtered to `is_ml_scored = True` | Big Number / Card | `COUNT(record_id)` |
| KPI card: ML anomaly rate | `fact_transactions` filtered to `is_ml_scored = True` | Big Number / Card | `AVG(is_ml_anomaly) * 100` |
| KPI card: Critical-risk suppliers | `dim_supplier` | Big Number / Card | `COUNTIF(risk_tier = "Critical")` |
| Monthly spend & anomaly trend | `dim_month` | Combo chart: bar (spend) + line, dual axis | X = `year_month`; bar Y = `total_spend` (colour by `period`); line Y = `ml_anomaly_rate_pct` |
| HHI trend | `dim_month` | Line chart | X = `year_month`, Y = `hhi` |
| Risk tier distribution | `dim_supplier` | Bar chart | X = `risk_tier` (sort Low→Critical), Y = `COUNT(supplier)` |
| Top 15 highest-risk suppliers | `dim_supplier` | Horizontal bar, Top N filter | X = `composite_risk_score`, Y = `supplier`, colour = `is_network_hub` |
| Category COVID-shock ranking | `dim_category` | Horizontal bar, Top N = 10, sort desc | X = `pct_change_pre_to_covid`, Y = `category` |
| Category deep dive table | `dim_category` | Table / heatmap | `category`, `total_spend`, `mean_anomaly_rate_pct`, `mean_hhi`, `share_of_total_spend_pct` |
| Anomaly vs rule-flag drill-through | `fact_transactions` | Scatter | X = `ml_anomaly_score`, Y = `rule_flag_count`, colour = `is_ml_anomaly` |

### Power BI specifics
- Import each of the 5 files through Get Data → Text/CSV, then specify the
  Model view relationships exactly as listed above (all "many" side on
  `fact_transactions`).
- For the dual-axis monthly panel, use a Line and Clustered Column Chart
  visual with `total_spend` on the column axis and `ml_anomaly_rate_pct` on
  the line's secondary axis.
- Specify a data category or sort order for `risk_tier` (Low, Medium, High,
  Critical) through Column tool → Sort by Column against a helper index if
  alphabetical ordering is not analytically appropriate.

### Tableau specifics
- Connect through Connect → Text File, place `fact_transactions.csv` on the
  canvas, then add the four dimension files as separate connections and
  define relationships (Data pane → "Edit Relationships") using the join
  keys listed above.
- For the dual-axis panel, place `total_spend` and `ml_anomaly_rate_pct` on
  the Rows shelf, then select the second field → Dual Axis. Axis
  synchronisation should remain disabled because the measures have materially
  different scales, consistent with `dashboard.py`.
- Apply the following consistent colour specification: Pre-COVID `#94a3b8`,
  COVID `#c1272d`, Post-COVID `#1f5fae`, and Low/Medium/High/Critical risk
  tiers `#94a3b8` / `#f4a259` / `#e07a5f` / `#c1272d` respectively, matching
  the Python-generated figures and dashboard elsewhere in this repository.
